# 금융 상품 비교 REST API Server

리더 : 오세진
팀원 : 박성연

금융감독원 금융상품통합비교공시 API를 활용해 정기예금 상품 정보를 수집하고, Django REST Framework 기반 API로 조회할 수 있도록 구현한 프로젝트입니다.

상품 기본 정보와 금리 옵션 정보를 분리해 저장하고, 상품 코드(`fin_prdt_cd`)를 기준으로 두 데이터를 연결합니다. 또한 Upstage API를 활용해 테스트용 금융 상품 더미 데이터를 생성하고, 생성된 데이터가 실제 서비스에서 사용할 수 있는 구조인지 검증하는 기능도 포함했습니다.

## 구현하면서 고려한 점


외부 API 호출, 금리 값 정규화, AI 더미 데이터 생성, 데이터 검증 로직을 `views.py`에 모두 작성하지 않고 `services/` 폴더로 분리했습니다. 이를 통해 View는 요청과 응답 처리에 집중하고, 실제 비즈니스 로직은 별도 모듈에서 관리할 수 있도록 했습니다.

### 결측 금리 처리

금융감독원 API 응답에서 금리 값이 비어 있는 경우가 있어 그대로 저장하면 숫자 필드 처리에서 문제가 생길 수 있었습니다. 그래서 `None` 또는 빈 문자열은 `-1`로 변환해 저장했습니다.

### API Key 보안 관리

금융감독원 API Key와 Upstage API Key는 코드에 직접 작성하지 않고 `.env` 파일에서 관리하도록 설정했습니다. `.env`는 Git에 올라가지 않도록 `.gitignore`에 포함했습니다.

---

## 어려웠던 점

### 1. 외부 API 응답 구조 파악

금융감독원 API는 상품 기본 정보와 옵션 정보가 각각 `baseList`, `optionList`로 분리되어 내려옵니다. 처음에는 이 데이터를 한 번에 저장하려고 해서 구조가 복잡하게 느껴졌습니다.

이를 해결하기 위해 상품 정보를 먼저 저장한 뒤, 옵션 저장 단계에서 `fin_prdt_cd`를 기준으로 연결된 상품을 찾아 외래키로 묶었습니다. 이 과정을 통해 외부 API 데이터를 그대로 DB에 넣는 것이 아니라, 프로젝트 모델 구조에 맞게 재구성하는 과정이 중요하다는 것을 알게 되었습니다.

### 2. 중복 데이터 처리

같은 API를 여러 번 호출하면 동일한 상품 코드의 데이터가 반복해서 저장될 수 있었습니다. 단순 `create()`를 사용하면 중복 데이터가 쌓이거나 unique 제약 조건 오류가 발생할 수 있어 `update_or_create()`를 사용했습니다.

이 방식 덕분에 이미 존재하는 상품은 업데이트하고, 없는 상품은 새로 생성하는 흐름으로 안정적으로 처리할 수 있었습니다.

## 배운 점

- Django REST Framework에서 Serializer를 활용해 모델 데이터를 JSON으로 변환하는 흐름을 익혔습니다.
- 외부 API 응답 데이터를 프로젝트 모델 구조에 맞게 정제하고 저장하는 방법을 배웠습니다.
- `ForeignKey`와 `related_name`을 사용해 상품과 옵션의 1:N 관계를 구성하는 방법을 이해했습니다.

## 최종 결과

정기예금 상품 데이터를 외부 API에 수집해 DB에 저장하고, 사용자가 상품 목록, 상품 상세 정보, 상품별 옵션, 최고 금리 상품을 조회할 수 있는 REST API 서버를 구현했습니다.

추가로 생성형 AI 기반 더미 데이터 생성 기능을 구현하면서, 외부 API 데이터뿐만 아니라 AI가 생성한 데이터도 서비스에서 활용하려면 구조화와 검증 과정이 필요하다는 것을 확인했습니다.
